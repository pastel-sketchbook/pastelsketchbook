One  of  the  most persistent  security  concerns  in container  orchestration  has  been  the shared  root  vulnerability.  Before Kubernetes  version  1.36,  the  root  user inside  a  container  represented  as  UID0 was  functionally  identical  to  the  root user  on  the  host  machine.  This configuration  meant  that  any  container escape  was  catastrophic  as  it  granted  an attacker  full  administrative  access  to the  underlying  host  node. This provides  essential  kernel  level  defense indepth.  Most  importantly,  it  achieves this  heightened  security  posture  without the  significant  performance  overhead typically  required  by  third  party sandboxing  tools  like  G  Visor  or  Aana containers.

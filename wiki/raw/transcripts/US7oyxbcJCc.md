Welcome  to  this  presentation.  Today  we are  diving  into  cloth  simulation,  a performance  study,  a  project  developed by  Pastel  Sketchbook.  This  study  focuses on  the  intersection  of  high  performance computing  and  real-time  graphics. Throughout  this  session,  we  will  explore the  practical  applications  of  data oriented  design  and  various  rendering optimization  techniques.  Crucially,  we will  examine  the  performance  divide between  web  assembly  and  native environments  utilizing  a  comparative analysis  of  implementations  in  Zigg  and Swift.  Our  goal  is  to  uncover  how  modern architectural  choices  can  bridge  the  gap between  web-based  and  native  performance for  demanding  simulations.  Let's  begin. Our  mission  was  to  bring  highfidelity physics  directly  to  the  desktop environment.  The  primary  goal  was  to develop  a  desktop  overlay  capable  of rendering  interactive  cloth  physics  that floats  seamlessly  above  the  user's wallpaper.  To  succeed,  the  solution needed  to  be  portable,  aesthetically pleasing,  and  technically  invisible  to system  resources,  ensuring  it  did  not interfere  with  the  user's  primary  tasks. To  achieve  this,  we  developed  a  modular architecture  divided  into  three  distinct layers.  At  the  top,  the  host  layer  is written  in  Swift  to  manage  platform specific  responsibilities  like rendering,  user  input,  and  windowing. This  communicates  through  a  bridge layer,  which  serves  as  a  WAM  and  CABI interchange.  At  the  base  we  have  the core  written  in  zigg.  This  layer leverages  data  oriented  design  to  handle the  heavy  lifting  of  physics  and mathematics.  The  primary  technical constraint  driving  this  design  is  the need  to  maintain  a  stable  60  frames  per second  while  calculating  approximately 2300  constraints  per  frame.  This architecture  allows  us  to  meet  those performance  demands  while  keeping  the resource  footprint  minimal.  Data oriented  design  or  DOD  represents  a fundamental  architectural  shift  from focusing  on  objects  to  prioritizing streams  of  data.  This  approach  is specifically  designed  to  maximize  CPU cache  efficiency.  On  the  left,  we  see the  traditional  method,  an  array  of strrus.  In  this  configuration,  different data  fields  are  interled,  which  often results  in  poor  cache  utilization because  the  CPU  pulls  in  unnecessary data  alongside  the  values  actually  being processed.  The  Zigg  way  shown  on  the right  utilizes  a  strruct  of  arrays.  By organizing  data  into  contiguous  streams, we  can  separate  hot  data  such  as position  coordinates  updated  every  frame from  cold  data  like  mass  or  pinning status  that  is  rarely  accessed.  This separation  ensures  that  the  CPU  cache remains  filled  with  relevant  information minimizing  memory  stalls.  Furthermore, this  layout  is  inherently  SIMD  ready, enabling  the  hardware  to  perform parallel  operations  on  multiple  data points  simultaneously  for  optimal performance.  The  core  physics  of  cloth simulation  is  built  upon  the  Verlet integration  method  as  shown  in  this equation.  To  determine  a  particle's  new position,  we  take  its  current  position and  add  the  change  in  position  from  the previous  frame  scaled  by  a  damping factor  to  account  for  air  resistance  or internal  friction.  We  then  add  the current  acceleration  multiplied  by  the square  of  the  time  step.  This  approach is  favored  in  computer  graphics  for  its stability  and  efficiency.  To  give  the cloth  its  physical  characteristics,  we apply  a  network  of  constraints represented  by  these  three  diagrams. Structural  constraints  connect  adjacent nodes  to  define  the  primary  shape  and resist  stretching.  Shear  constraints  run diagonally  to  prevent  the  mesh  from distorting  or  skewing  under  stress. Finally,  bending  constraints  connect nodes  that  are  two  units  apart.  These are  essential  for  managing  how  the fabric  folds  and  ensuring  it  maintains  a realistic  surface  curvature.  In  a practical  environment,  these  internal physics  are  influenced  by  external  input factors.  Gravity  provides  a  constant downward  pull.  Directional  wind  adds dynamic  movement  and  lift,  and  mouse interactions  allow  for  real-time manipulation  and  user  engagement  with the  simulated  fabric.  Let's  examine  our first  major  performance  hurdle,  the  cost of  aesthetics.  The  primary  issue  stemmed from  a  naive  implementation  of  a  pastel glow  effect,  which  required  rendering three  distinct  layers  for  every  single line,  the  core,  mid,  and  outer  layers. For  a  grid  size  of  25x  25,  which encompasses  625  points,  we  were rendering  approximately  2352 visible  lines.  Because  of  the  triple layer  requirement,  this  ballooned  into nearly  7,000  draw  calls.  This  high  call count  combined  with  the  expensive overhead  of  creating  CG  color  objects within  our  inner  loops  resulted  in performance  dropping  below  60  frames  per second,  creating  a  significant bottleneck  for  a  smooth  user  experience. Optimization  through  batched  rendering is  essential  for  maintaining  high performance  in  complex  visual environments.  In  a  naive  implementation, rendering  an  intricate  scene  might require  approximately  7,000  individual draw  calls,  which  places  a  significant burden  on  the  hardware.  By  grouping elements  into  discrete  buckets  based  on shared  properties  like  color,  we  can dramatically  streamline  this  process.  As illustrated,  moving  to  a  batched approach  results  in  a  99.7% reduction  in  draw  calls,  dropping  the count  to  just  24.  We  have  structured  our rendering  tiers  to  provide  flexibility across  different  hardware  profiles.  The highquality  setting  utilizes  eight  color buckets  to  achieve  24  calls.  The  medium quality  setting  removes  the  outer  glow layer  to  reach  approximately  4,700  calls and  the  fast  quality  setting  limits  glow to  structural  lines  for  roughly  2350 calls.  This  strategy  is  defined  by  a singular  philosophy.  We  are  sacrificing microscopic  interpolation  to  ensure superior  macroscopic  performance.  This slide  details  a  method  for  achieving three-dimensional  depth  through normalbased  lighting  within  a  2D environment.  Our  specific  constraint requires  that  the  simulation  operate  in X  and  Y  coordinates  only  without  the  use of  GPU  shaders.  To  overcome  this,  we infer  a  virtual  Z-axis  based  on  the relative  compression  of  the  mesh.  When the  mesh  is  expanded,  the  surface  is treated  as  flat  with  a  consistent  upward normal.  When  the  mesh  is  compressed,  it is  interpreted  as  bulging  which  changes the  orientation  of  the  surface  normals. We  calculate  these  normals  by  taking  the cross  productduct  of  two  edges  within the  mesh.  By  utilizing  this  virtual  Z derived  from  mesh  density,  we  can  apply lighting  calculations  that  give  2D objects  a  realistic  sense  of  volume  and curvature. Instead  of  compiling  our  ZIG code  to  web  assembly,  we  now  compile  it directly  into  a  dynamic  library  or  DIL. The  Swift  host  then  loads  this  library using  DLOP  and  interfaces  with  it  via function  pointers.  This  architectural change  yielded  a  dramatic  performance improvement,  moving  from  approximately  7 frames  per  second  on  WAM  to  a  rock  solid 62.5  FPS.  Crucially,  the  overhead remains  negligible,  costing  only  about 30  micro  for  the  initial  pointer  lookup. The  hybrid  architecture  verdict highlights  the  specific  strengths  of both  native  and  web  assembly  approaches. Use  native  for  desktop  applications, heavy  compute  tasks,  and  development iteration  to  take  full  advantage  of  raw processing  power  and  speed.  Use  WASOM for  web  deployment,  sandboxing,  and portability  to  ensure  secure  and consistent  behavior  across  different environments.  The  optimal  strategy  is  to develop  with  native  for  speed  and  test with  WAM  for  compatibility.  Engineering for  longevity  is  a  primary  focus  for  our team,  particularly  because  long-running desktop  overlays  are  highly  susceptible to  memory  leaks.  To  mitigate  this  risk, we  have  implemented  a  three-pronged strategy.  First,  we  rely  on  fixed buffers  that  are  allocated  once  at startup.  By  avoiding  runtime  resizing, we  eliminate  common  sources  of  heap fragmentation.  Second,  we  enforce  strict state  hygiene  through  a  rigorous  balance of  save  gate  and  restore  gstate  calls. This  ensures  that  the  graphics  state  is always  predictably  managed.  Third,  we have  integrated  proactive  monitoring utilizing  automated  tests  that  flag  any memory  growth  exceeding  10%  over  a 30inut  period.  These  combined  efforts allow  us  to  maintain  a  stable  and predictable  total  footprint  of approximately  15  megabytes.  Performance is  a  feature,  not  an  afterthought.  While aesthetics  define  our  constraints, balance  remains  the  ultimate  objective. To  achieve  the  results  seen  in  this cloth  simulation,  we  focused  on  three key  technical  pillars.  In  physics,  we utilized  data  oriented  design  with  a structure  of  arrays  approach  to  maximize cache  efficiency.  For  rendering,  we achieved  a  99.7%  reduction  in  draw calls,  significantly  minimizing  CPU  to GPU  overhead.  Finally,  our  compute optimizations  delivered  an  1100  times speed  up  over  the  native  baseline.  This project  illustrates  how  extreme performance  and  highquality  aesthetics can  be  successfully  balanced.

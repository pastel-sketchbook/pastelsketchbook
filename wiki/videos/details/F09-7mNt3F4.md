## Summary

This video provides a comprehensive blueprint for designing Azure Kubernetes Service networking, covering subnet sizing, CNI model comparison, and cluster scaling strategy. It explains that Azure reserves 5 IP addresses per subnet (not the standard 2), using the formula usable IPs = 2^(32-prefix) - 5, and details how these reserved addresses serve the default gateway, Azure DNS mapping, and infrastructure services. The presentation compares different CNI models to balance performance and simplicity.

## Key Takeaways

- Azure reserves 5 IP addresses per subnet (network, broadcast, default gateway, and two for Azure DNS mapping), unlike traditional networking which typically reserves only 2.
- The subnet sizing formula for Azure is usable IPs = 2^(32 - CIDR prefix) - 5, and failing to account for this leads to IP exhaustion in production clusters.
- Different CNI models (Azure CNI, kubenet, Azure CNI Overlay) offer distinct trade-offs between IP address consumption, performance, and operational simplicity.
- Capacity planning must account for both current pod density and future scaling needs, as running out of subnet IPs requires disruptive re-architecture.
